title: Programming is not the same as designing software
descripcion: What I took away from Alexander Shvets's "Dive Into Design Patterns".
fecha: 2026-03-13
---

I've just read *Dive Into Design Patterns* by Alexander Shvets, and it left me with one clear idea: programming is not the same as designing software.

## From "it works" to "it can be maintained"

When you start out, you focus on making the code work. Over time a harder problem shows up: making that code maintainable, scalable and easy for someone else to understand.

That's where design patterns come in. The book makes it clear that they are not magic recipes or snippets to copy and paste. They are proven solutions to problems that come up again and again when we build software.

## Once you see them, they're everywhere

The most interesting part is that, once you understand them, you start recognising them everywhere: in the frameworks you use, in well-designed architectures, and even in code you wrote years ago and would now write differently.

## Think before you write

For me, the value of learning patterns isn't memorising them, but thinking more carefully about the structure of the software before writing any code. Writing code is only part of the job; designing the system well is what makes the difference and what lets it grow without breaking.

If you work in software development, it's one of those books worth reading at least once.
